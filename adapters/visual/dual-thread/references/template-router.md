# 对话模板路由

## 原则

模板只用于：

- 新对话开场。
- 新任务边界。
- 发生上下文压缩。
- 需要独立视觉会话。
- 进入最终验收或新版本。

任务已经开始后，用户继续提供需求、反馈、bug 现象或局部调整时，直接在当前任务中处理，不要重复要求用户套模板。

## 推荐时机

只在出现明确边界时推荐下一个模板，每个边界最多推荐一次：

| 当前情况 | 推荐模板 | 推荐理由 |
|---|---|---|
| 新项目第一次使用工作流 | 项目首次初始化 | 创建目录、AGENTS 规则和 VISION-FACTS |
| 开始一个新交付 | 主开发会话标准开场 | 需要预检、预算、边界和收尾要求 |
| 同一会话中的普通后续反馈 | 不推荐模板 | 直接在当前任务继续 |
| 出现普通识图问题 | 普通识图 | 本地调用视觉预处理并用 JSON 回传 |
| 需要主观视觉判断 | 独立视觉会话开场 | 防止图片进入主开发上下文 |
| 收到视觉结果 | 回到主会话接收视觉结果 | 只合并事实，不重看图片 |
| 发生上下文压缩 | 上下文过长或发生压缩 | 立即收尾并换新任务 |
| 用户给出明确 bug 复现 | Bug 修复任务 | 固定现象、复现、预期和验证 |
| 进入视觉或 UI 验收 | UI 或视觉验收任务 | 强制先证据后改布局 |
| 里程碑完成，准备验收 | 最终验收任务 | 不改功能，只判断 PASS/FAIL |
| 开始下一版本 | 新版本继续开发 | 从 HANDOFF 冷启动，不重做已确认项 |
| 大量图片需要同一问题 | 图片批处理 | 统一缓存键、限制调用和停止条件 |
| CC Switch 模型异常 | provider adapter: `deepseek-cc-switch` | 备份并修复模型目录 |

## 输出格式

默认只给一行：

```text
建议切换模板：《<模板名>》。原因：<当前已经到达的边界>。
```

用户要求“给我完整模板”时，再输出完整可复制内容。

## 推荐门槛

- 当前交付尚未完成时，不推荐“最终验收”。
- 只是同一交付内的小修小补，不推荐任何模板。
- 只有读取新图片时，才推荐视觉相关模板。
- 只有发生压缩或进入新任务边界时，才推荐换会话。
- 用户明确说“不用推荐模板”后，当前任务内保持安静，直到任务结束或发生压缩。

## 推荐后的动作

- 如果仍在当前交付内，推荐一行后继续解决当前问题。
- 如果当前任务已结束，推荐后停止写入，等待用户开新对话。
- 如果发生压缩或高风险循环，先回填 HANDOFF，再推荐下一模板。
